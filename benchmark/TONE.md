# Отдельный тест T-one

Запускается только **Silero VAD → T-one**, последовательно для всех 100 записей.
Whisper, GigaAM, CAM++, эмоции и GigaChat не запускаются. Продовые API не вызываются,
контейнеры других сервисов не останавливаются. GPU остаётся общей: дополнительная
нагрузка может влиять на скорость рабочих сервисов и теста.

Из корня `temptest` на сервере:

```bash
BENCH_GPU=0 \
BENCH_GPU_MIN_FREE_MIB=12288 \
BENCH_GPU_MAX_UTIL=100 \
BENCH_GPU_RESERVE_MIB=3072 \
bash benchmark/run-tone.sh ../audio
```

Логи сразу видны в терминале и одновременно сохраняются. Не закрывайте SSH во время
обычного запуска; для устойчивой сессии запускайте эту команду внутри `tmux`.
`Ctrl+C` останавливает только контейнер текущего теста. Контейнеры после теста,
образы и результаты сохраняются; удаления и общего `prune` нет.

Если на сервере сохранён предыдущий тест, добавьте к команде:

```bash
  --reference-run benchmark-results/20261008-163940-3995135
```

Путь должен существовать **на сервере**. Флаг необязателен: он проверяет число,
имена, порядок, SHA256 и длину всех подготовленных PCM-записей, переносит настройки
VAD и исходный прогрев. При несовпадении распознавание не начинается. Исходные
результаты открываются только для чтения. Число CPU-потоков должно совпадать с
исходным тестом (обычно `BENCH_THREADS=4`). Без флага сравнение корпуса нужно сделать
позже по сохранённым SHA256; принадлежность к прежним 100 записям не предполагается.

Тест явно задаёт `provider=cuda`, `device=0`; штатный T-one в исходном мониторе
использует CPU по умолчанию. [Официальный API sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/python/sherpa_onnx/online_recognizer.py)
позволяет выбрать CUDA. Проверяются CUDA wheel, совместимость двух ONNX Runtime и
провайдер VAD. Сообщение sherpa о переходе на CPU делает замер неуспешным.
Это выбор CUDA-провайдера; отдельные операции ONNX и подготовка звука могут выполняться CPU.

Используется готовый CUDA-образ прежнего стенда, чтобы сохранить проверенные
библиотеки и избежать установки через `apt`. Если образ удалён, скрипт сначала
соберёт его, **не поднимая старые сервисы**. В новом слое скачиваются только веса
T-one, архив проверяется по SHA256. При сборке нужны GitHub и источники зависимостей;
аудио в сборку не попадает. Контейнер обработки работает **без сети**, записи
подключены только для чтения. GPU-модели и обработка не стартуют до проверки ресурсов.

Для каждой записи создаётся отдельный процесс, как в предыдущем сокращённом тесте
GigaAM. Загрузка и прогрев первых 30 секунд выбранной записи измеряются отдельно.
После прогрева замеряется обработка всей записи и отдельно сумма вызовов ASR.
Общий вход — моно PCM16 16 кГц. T-one требует 8 кГц: фильтрация и пересчёт частоты,
добавленная тишина 0,3 с перед / 1 с после каждого фрагмента включены в ASR.
Пауза между записями 5 с, декодирование, запись логов родителем и создание отчёта
в итоговую скорость обработки не включаются. Полные ответы печатаются после
замера; запись этих логов не включается в его время. Временные метки T-one скорректированы на 0,7 с,
как в исходной интеграции; это не ручная проверка времени произнесения слов.

Результаты: `benchmark-results/tone-ДАТА-ВРЕМЯ-PID/`:

- `отчёт.html` — автономная тёмная страница: время каждой записи, распределение
  времени по этапам, все тексты. Открывается на ПК без сервера и интернета.
- `итоги.json`, `замеры.csv`, `условия.json` — измерения, настройки, версии,
  контрольные суммы аудио, состояние всего прогона.
- `записи/0001/…` — исходный текст, ответ, реплики/слова с метками времени,
  вероятности VAD, паузы, журнал нативного процесса, подготовка и прогрев.
- `логи/запуск.log`, `логи/t-one.log`, `прогон.log`, `логи/gpu.csv` — полные
  журналы запуска, обработки и нагрузка всей GPU каждые 2 с.
- `диагностика.tar.gz` — готовый архив для разбора, без аудио и моделей;
  содержит тексты разговоров. Временные WAV удаляются после остановки.

Прогон закончен полностью при состоянии `Завершён`, 100 результатов и коде запуска 0.
Ошибки и прерванный прогон тоже сохраняются, но не выдаются за успешные 100 записей.
Скорость сама по себе не доказывает качество: правильность слов, сумм и дат
проверяется по аудио. T-one возвращает числа словами, исходные ответы не очищаются.
