# Изолированный стенд Whisper и GigaAM

`run.sh` управляет только проектом `speech-comparison`: собственный Whisper
обрабатывает весь корпус, останавливается, затем запускается полный GigaAM.
После него тестовая Ollama останавливается и тот же корпус проходит GigaAM
первой линии: только VAD и ASR, без голосов, эмоций и GigaChat.
Порядок файлов одинаковый, один файл за раз, между HTTP-запросами пауза ≥5 с.
Продовые контейнеры и их API не используются. Запуск на GPU выполняет владелец;
локальные проверки используют заглушки без моделей и реальных запросов.

Команды для H100 и структура результатов — [SERVER.md](SERVER.md).

Если Whisper завершился, а запуск остановился до первого замера GigaAM,
продолжите командой `bash benchmark/run.sh ../audio --resume-gigaam benchmark-results/<ID>`.
В новый отчёт переносятся прежние замеры Whisper, затем измеряются полный GigaAM
и первая линия. Исходные результаты сохраняются; восстановленный PCM сверяется
по SHA256. Готовый GigaChat используется из собственного кеша без повторной загрузки.

Для отдельного прогона GigaAM используйте `bash benchmark/run.sh ../audio --gigaam-only`.
Подготовка звука выполняется тем же декодером в CPU-контейнере без сети;
сервер и модели Whisper не запускаются. Результаты GigaAM, графики и архив
сохраняются в новый каталог; прежние результаты Whisper остаются отдельно.

## Образы и подготовка

Оба Dockerfile основаны на закреплённом CUDA-образе `hwdsl2/whisper-server`
с digest `de716f26601229179eb4ba62d07e7a5ed4167c5290786281cd06535fdf2a97d6`.
Его готовые CUDA/Python/PyAV используются без установки системных пакетов
через apt. GigaAM ставится из архива конкретного коммита, без зависимости от git.
Окружение GigaAM `/opt/gigaam-venv` отдельно от библиотек базового Whisper.

Whisper: faster-whisper 1.2.1, CTranslate2 4.8.1, large-v3, CUDA/float16,
русский язык, beam 5, CPU threads 2. Штатный VAD и алгоритм образа сохраняются;
подготовка звука и вспомогательные операции могут выполняться на CPU.

GigaAM: официальный v3_e2e_rnnt и emo на PyTorch CUDA, fp16 encoder/fp32 head,
Silero VAD и CAM++ на CUDA, локальная GigaChat через Ollama полностью на GPU.
Закреплённые ONNX Runtime GPU 1.24.4 и sherpa-onnx 1.13.4+cuda12.cudnn9
проверяются на совместимость. Неподходящие версии/CPU fallback останавливают тест.

Интернет нужен только для сборки/подготовки. Контейнеры загрузки весов не имеют
GPU и папки разговоров. Загрузчики используют `host` для выхода
в интернет через сеть сервера; сети обработки записей остаются внутренними.
Ollama для подготовки слушает только `127.0.0.1:11435`; готовность своего
контейнера проверяется перед скачиванием. Настройки сети/порта и отдельные
логи скачиваний описаны в [SERVER.md](SERVER.md).
Whisper загружает веса в собственный `benchmark-cache/whisper`,
GigaAM — в свой кеш, Ollama — в volume своего проекта. Кеши прода не подключаются.

## Сеть и защита от подключения к проду

Тестовый Whisper и клиент работают в отдельной сети `internal: true`. Порт
не публикуется на хост. Адрес фиксирован: `http://whisper-bench:9000/v1`.
Клиент тестового режима отвергает остальные адреса и проверяет метаданные
сервиса: принадлежность стенду, модель, фактическое размещение CUDA/float16.
Старые ключи/адреса из `.env` не передаются контейнерам.

API Whisper запускается прямо из закреплённого образа, обходя vendor `run.sh`,
который может делать внешние запросы при старте. Только локальные веса,
без diarization и автозагрузок. Телеметрия HF отключена.
GigaAM/Ollama используют свою внутреннюю сеть; облачные функции Ollama
и автозагрузка её модели при обработке запрещены. Записи не отправляются
на внешние сервисы.

Управление Docker всегда ограничено конкретным Compose-файлом и проектом.
При ошибке прекращаются новые записи, сохраняются логи и останавливается стенд.
Общая GPU остаётся общим ресурсом: CPU/RAM-квоты и резерв памяти не дают
аппаратной изоляции VRAM или вычислений от продовых процессов.

## Таймеры и сравнимость

1. Каждая запись один раз преобразуется в моно PCM16 WAV 16 кГц. В готовом
   образе используется PyAV; если ffmpeg доступен, используется он. Обе
   системы читают этот же WAV; SHA256 PCM проверяется до измеряемых вызовов.
   Подготовка и её длительность записываются отдельно.
2. Тестовый Whisper загружается один раз на весь корпус. Его CUDA/float16
   и версии проверяются, первые 30 секунд выбранного файла используются
   для прогрева. Прогрев отдельно сохранён и не входит в таблицу записей.
3. Whisper: время от начала HTTP-запроса до получения ответа целиком,
   включая передачу WAV и серверную обработку. `server_processing_seconds`
   пустое — сервер не сообщает чистое ASR-время. Сохраняются полный verbose_json,
   сегменты, параметры, HTTP-статус, байты ответа и объединённая длительность
   сегментов с текстом. Это длительность найденных сегментов, не точность.
4. После корпуса тестовый Whisper останавливается. Его контейнер сохраняется. GigaAM
   стартует только после успешной фазы Whisper и подтверждения его остановки.
5. GigaAM запускает каждую запись в отдельном процессе с загрузкой моделей
   и прогревом вне основных таймеров. Полный цикл включает VAD, ASR, CAM++,
   эмоции и законченный JSON-разбор LLM. ASR — сумма вызовов с CUDA sync.
   После записи модели и LLM выгружаются. Такой жизненный цикл GigaAM отражён
   в условиях и подробных логах; время всей подготовки не скрывается.
6. Первая линия — отдельный реальный прогон после остановки тестовой Ollama.
   Использует те же VAD, модель ASR, параметры, PCM WAV и файл прогрева.
   CAM++, эмоции и GigaChat не загружаются и не вызываются. Контейнер
   `first-line` не имеет сети. Подготовка и прогрев каждой записи исключены
   из замера и сохранены отдельно, как у полного GigaAM.

Для сопоставимости все три режима читают общий моно WAV. Исходные число
каналов, частота и размер файла записываются в условиях. Этот тест измеряет
упрощённую обработку первой линии на том же смешанном корпусе; восстановление
ролей оператор/клиент по стереоканалам здесь не выполняется.

Штатная нагрузка сервера и порядок фаз влияют на замеры. Сравниваются
самостоятельный сервис Whisper и локальный полный конвейер GigaAM.
Проценты времени рассчитываются по полностью успешным парам; ошибки
в итоговые суммы не входят. Для точности нужны ручные эталоны/WER.

## Результаты

Одна папка запуска содержит `прогон.log`, `условия.json`, `сводка.csv`,
`отчёт.md`, самодостаточный `отчёт.html`, `графики/*.svg`, логи сервера Whisper,
Ollama, общую GPU CSV и подробные результаты каждого файла в `записи/0001/…`.
Графики обновляются после каждой записи. Общая GPU CSV включает нагрузку
всех процессов сервера, а не только стенда.

В `итоги.json` — количество успешных/ошибочных/незапущенных записей каждого
режима, среднее, медиана, p90/p95, суммы времени, производительность за 15 минут
и сравнение на одинаковых успешно обработанных тройках. `замеры.csv` содержит
300 строк для 100 записей: обработка, загрузка, прогрев, вызовы/ошибки этапов
и SHA256 входа. Частичный прогон явно отмечается, будущие фазы остаются pending.

На каждую запись сохраняются `whisper.json/.txt`, `gigaam.json/.txt` и
`gigaam_first_line.json/.txt`. У обоих режимов GigaAM дополнительно есть
`*-подготовка.json`, `*-прогрев.json`, `*-задание.json`, `*-процесс.log`.
Результаты содержат все реплики, события, вызовы моделей с границами времени,
токены ASR и их времена, VAD-фрагменты с вероятностями и интервалы пауз.
Паузы означают участки, которые VAD не отнёс к речи; это оценка детектора.

Графики процентов используют `timing.exclusive_wall_percent`: параллельная
работа нескольких этапов выделена отдельно, сумма равна 100%. Также сохранены
суммы вызовов каждого этапа, которые могут пересекаться. Загрузка и прогрев
не смешиваются с этими долями. Полная длительность фаз с подготовкой и записью
отчётов указана в `условия.json → phases`.

`диагностика.tar.gz` содержит эти файлы и тексты разговоров, исключает аудио,
веса и секреты. После завершения удаляются временные WAV; контейнеры
останавливаются и сохраняются вместе с сетями для просмотра логов.
Исходные файлы, отчёты и кеши моделей остаются. Ничего автоматически не отправляется.

Исходники можно упаковать без `.env`, записей, кешей и результатов:

```bash
python3 benchmark/package.py --out ../speech-comparison-server.tar.gz
```

`bash benchmark/run-tone.sh ../audio`. Запуск, проверка корпуса предыдущего теста
и описание результатов — в [TONE.md](TONE.md).
