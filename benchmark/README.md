# Устройство стенда

Три отдельных теста, у каждого свой скрипт запуска, Compose-проект и папка результатов:

| Тест | Скрипт | Compose-проект | Подробности |
|---|---|---|---|
| Whisper large-v3 | `run.sh` | `speech-comparison` | этот документ |
| GigaAM v3 через TensorRT | `run-gigaam-trt.sh` | `speech-comparison-gigaam-trt` | [GIGAAM-TRT.md](GIGAAM-TRT.md) |
| T-one через TensorRT | `run-tone-trt.sh` | `speech-comparison-tone-trt` | [TONE-TRT.md](TONE-TRT.md) |

Порядок файлов одинаковый, один файл за раз. Тесты TensorRT обрабатывают все записи папки подряд, без пауз.
Whisper ждёт ровно 100 записей (`--expected-files`) и делает паузу 5 с между запросами.
Продовые контейнеры и их API не используются. Запуск на GPU выполняет владелец;
локальные проверки используют заглушки без моделей и реальных запросов.
Команды для H100 — [SERVER.md](SERVER.md).

Голоса, эмоции и языковая модель в стенде не запускаются. GigaAM идёт по
урезанному flow: поиск речи → распознавание → паузы.

## Общее для всех тестов

Каждая запись один раз преобразуется в моно PCM16 WAV 16 кГц; SHA256 PCM
проверяется до измеряемых вызовов. Подготовка и её длительность записываются
отдельно и в замеры не входят. Исходные число каналов, частота и размер файла
сохраняются в условиях. Роли оператор/клиент по стереоканалам не восстанавливаются.

Тесты TensorRT принимают `--reference-run benchmark-results/<прогон>`: имена
файлов, SHA256 PCM и запись прогрева сверяются с прежним прогоном.

Управление Docker всегда ограничено своим Compose-файлом и проектом.
При ошибке прекращаются новые записи, сохраняются логи и останавливается стенд.
Общая GPU остаётся общим ресурсом: CPU/RAM-квоты и резерв памяти не дают
аппаратной изоляции VRAM или вычислений от продовых процессов.

## Whisper

`run.sh` собирает клиентский образ, скачивает веса, поднимает собственный
сервер, прогоняет корпус и останавливает сервер.

Образ основан на закреплённом CUDA-образе `hwdsl2/whisper-server`
с digest `de716f26601229179eb4ba62d07e7a5ed4167c5290786281cd06535fdf2a97d6`.
Его готовые CUDA/Python/PyAV используются без установки системных пакетов.

Whisper: faster-whisper 1.2.1, CTranslate2 4.8.1, large-v3, CUDA/float16,
русский язык, beam 5, CPU threads 2. Штатный VAD и алгоритм образа сохраняются;
подготовка звука и вспомогательные операции могут выполняться на CPU.
Несовпадение версий или переход на CPU останавливают тест.

### Сеть и защита от подключения к проду

Тестовый Whisper и клиент работают в отдельной сети `internal: true`. Порт
не публикуется на хост. Адрес фиксирован: `http://whisper-bench:9000/v1`.
Клиент отвергает остальные адреса и проверяет метаданные сервиса:
принадлежность стенду, модель, фактическое размещение CUDA/float16.
Старые ключи/адреса из `.env` не передаются контейнерам.

API Whisper запускается прямо из закреплённого образа, обходя vendor `run.sh`,
который может делать внешние запросы при старте. Только локальные веса,
без diarization и автозагрузок. Телеметрия HF отключена. Записи не
отправляются на внешние сервисы.

Интернет нужен только для сборки и подготовки. Контейнер загрузки весов
не имеет GPU и папки разговоров; он использует сеть сервера (`host`).
Веса лежат в собственном `benchmark-cache/whisper`. Кеши прода не подключаются.

### Что измеряется

1. Сервер загружается один раз на весь корпус. Его CUDA/float16 и версии
   проверяются, первые 30 секунд выбранного файла используются для прогрева.
   Прогрев отдельно сохранён и не входит в таблицу записей.
2. Замер — время от начала HTTP-запроса до получения ответа целиком,
   включая передачу WAV и серверную обработку. `server_processing_seconds`
   пустое — сервер не сообщает чистое ASR-время.
3. Сохраняются полный verbose_json, сегменты, параметры, HTTP-статус, байты
   ответа и объединённая длительность сегментов с текстом. Это длительность
   найденных сегментов, не точность.
4. При HTTP-ошибке или таймауте следующие записи не отправляются; повторов нет.

### Результаты

Папка запуска содержит `прогон.log`, `условия.json`, `итоги.json`, `замеры.csv`,
`сводка.csv`, `отчёт.md`, самодостаточный `отчёт.html`, `графики/*.svg`, логи
сервера, общую GPU CSV и результаты каждого файла в `записи/0001/whisper.json`
и `whisper.txt`. Отчёт обновляется после каждой записи. Общая GPU CSV включает
нагрузку всех процессов сервера, а не только стенда.

В `итоги.json` — количество успешных, ошибочных и незапущенных записей,
среднее, медиана, p90/p95, сумма времени и производительность за 15 минут.
Частичный прогон явно отмечается: необработанные записи остаются `pending`.

`диагностика.tar.gz` содержит эти файлы и тексты разговоров, исключает аудио,
веса и секреты. После завершения удаляются временные WAV; контейнеры
останавливаются и сохраняются вместе с сетями для просмотра логов.
Исходные файлы, отчёты и кеши моделей остаются. Ничего автоматически не отправляется.

## Образы тестов TensorRT

Клиенты GigaAM и T-one собираются из `Dockerfile.tone-trt-benchmark` поверх
общего образа библиотек `speech-comparison:4.0.0-gigaam-cuda`
(`Dockerfile.benchmark`: PyTorch, gigaam, ONNX Runtime, PyAV). Если общего
образа нет, скрипт запуска собирает его через `compose.trt-base.yml`.
Сервер моделей — официальный `nvcr.io/nvidia/tritonserver:25.06-py3`.

## Передача исходников

Исходники можно упаковать без `.env`, записей, кешей и результатов:

```bash
python3 benchmark/package.py --out ../speech-comparison-server.tar.gz
```
