# Рабочий Whisper через API и полный цикл GigaAM на GPU

`run.sh` сначала обрабатывает весь корпус через существующий Whisper, затем
через отдельный Docker-стенд GigaAM. Рабочие `whisper-asr`, `model-proxy` и vLLM
не запускаются, не останавливаются, не перезапускаются и не перенастраиваются.
Запуск выполняет владелец. Код проверяется с заглушками без реальных запросов
на сервер и без GPU inference. Подробная серверная инструкция — [SERVER.md](SERVER.md).

## Запуск

Нужны Linux x86-64, Bash, flock, tar, timeout, NVIDIA-драйвер, Docker/Compose,
доступ GPU из контейнеров и интернет для подготовки образов и весов.

```bash
cp -n benchmark/server.env.example .env
# В .env задайте WHISPER_API_KEY — ключ клиента model-proxy.
BENCH_GPU=0 bash benchmark/run.sh /srv/speech-test/audio
```

Папка входа подключается только для чтения, поддерживаются WAV, MP3, M4A, FLAC,
OGG, OPUS, AAC, MP4, WMA, включая подпапки. По умолчанию ожидается ровно 100
файлов. Проверка количества и размеров происходит до первого аудиозапроса.
Одна запись ограничена 30 минутами и 64 МиБ подготовленного PCM WAV.
Для контрольного запуска на двух файлах используйте `--expected-files 2`.
Стандартный прогрев GigaAM — первые 30 секунд первой записи с речью.
Путь `--warmup-file` указывается внутри `/recordings`.

## Как защищается рабочий Whisper

- Один HTTP-запрос за раз; пауза не менее 5 секунд между записями.
- Проверка `/health` перед следующим аудиозапросом. Если сервис занят и проверка
  не ответила за 10 секунд, новые записи не отправляются.
- Один GET `/v1/models` до распознавания: модель должна уже быть доступна.
- Только POST `/v1/audio/transcriptions`; нет управления моделью или сервисом.
- Нет повторов, перенаправлений и прокси из окружения. На 429, 503, любой другой
  HTTP-ошибке, некорректном ответе или обрыве весь прогон прекращается.
- После клиентского таймаута сервер может продолжать работу над последним
  запросом. Стенд не отправляет его повторно и не переходит к GigaAM.
- Рабочая модель Whisper остаётся в VRAM на протяжении обеих фаз.
- Лёгкий контейнер клиента не получает GPU; лимит его RAM — 2 ГиБ.
- Блокировка предотвращает одновременные запуски из одной папки стенда.

На общей GPU невозможно гарантировать отсутствие задержек других сервисов:
нужно окно без посторонних модельных вычислений. Резерв памяти и квоты снижают
риск; это не аппаратное ограничение VRAM для GigaAM.

Перед началом и непосредственно перед GigaAM проверяются:
свободная VRAM ≥ 16 ГиБ, загрузка GPU ≤ 10%, доступная RAM ≥ 20 ГиБ,
свободный диск ≥ 32 ГиБ на файловых системах результатов, кеша и Docker.
При недостатке стенд завершается с кодом 42, не останавливая рабочие сервисы.
Контейнер GigaAM ограничен 8 ГиБ RAM, Ollama — 10 ГиБ RAM; CPU — 4 потока,
ядра 0–3 по умолчанию. Это ограничения RAM, а не VRAM.

Во время прогона `nvidia-smi` опрашивается примерно каждые 2 секунды. Если во время
GigaAM свободная VRAM опустилась ниже 4 ГиБ или мониторинг перестал работать,
останавливаются только одноразовый контейнер текущего прогона и Ollama стенда.
Проверяется резерв и после загрузки моделей/прогрева. Между файлами все модели
GigaAM и её LLM выгружаются. Порог не исключает коротких скачков между опросами.

Порог запуска задаётся `BENCH_GPU_MIN_FREE_MIB`, резерв — `BENCH_GPU_RESERVE_MIB`,
порог RAM — `BENCH_MIN_RAM_MIB`; переменные передаются в окружении команды запуска.
Порог свободного диска задаётся `BENCH_MIN_DISK_MIB`.
Их значения записываются в условия. Не снижайте их без оценки реального пика.

## Данные и сеть

Whisper API разрешён только по локальному IP или localhost, без ключа в URL.
Внутри контейнера localhost означает сам контейнер; используйте адрес сервера.
Авторизация передаётся заголовком и не сохраняется в результатах.
На вашем сервере используется `http://10.220.21.2:8002/v1`.

Весовые файлы GigaAM/Emo и GigaChat скачиваются отдельно. Контейнеры подготовки
не имеют подключения папки разговоров и доступа к GPU. Затем GigaAM и Ollama
работают в Docker-сети `internal: true`, без внешних портов и выхода наружу.
HF telemetry и облачные функции Ollama отключены; автозагрузка LLM внутри
конвейера запрещена. Кеши переиспользуются. Исходники в архиве не содержат
аудио, .env или моделей. Приватность рабочего Whisper зависит также от его
собственной конфигурации; стенд её не меняет.

## Таймеры и сравнимость

Общий моно WAV 16 кГц PCM16 создаётся один раз; SHA256 PCM сохраняется и
проверяется обеими системами. Подготовка не входит в основные времена.

- Whisper: полный HTTP-запрос, включая передачу WAV, очередь сервиса и ответ.
  Чистое время ASR не выдумывается: поле `server_processing_seconds` пустое.
  Дополнительного аудиопрогрева рабочего сервиса нет.
- GigaAM ASR: сумма реальных вызовов, включая пустые ответы, с CUDA sync.
- GigaAM полный цикл: VAD, ASR, CAM++, эмоции, завершённый JSON-разбор LLM.
  Загрузка, прогрев и запись результатов исключены. Каждая запись — отдельный
  процесс, затем явная выгрузка LLM. Настройки моделей те же, что в GPU-стенде.

Это сравнение работающего сервиса с локальным конвейером. Порядок фаз, очередь
API и посторонняя нагрузка фиксируются как ограничения. Проценты рассчитываются
по успешным парам, а не переносятся с прежнего локального прогона.

«Сегменты с текстом, с» — длительность объединения интервалов Whisper с непустым
текстом; это не точный объём речи и не оценка точности. Времена этапов GigaAM
пересекаются, их нельзя складывать в части общего времени.

## Логи, графики и передача результатов

Вся диагностика одного запуска находится в `benchmark-results/<дата-ID>/`:

- `прогон.log`: русский подробный журнал с датами, PID, загрузкой, прогревом,
  каждым сегментом Whisper, вызовами ASR/CAM++/эмоций GigaAM, репликами,
  вероятностями эмоций, объединением голосов, ответом LLM и ошибками.
  VAD сохраняет общую длительность, число вызовов и ошибок; каждая порция
  100 мс отдельно в журнал не выводится. Трасса моделей собирается в памяти,
  записывается после измерения.
- `логи/запуск.log`, `ollama.log`, `загрузка-ollama.log`, `gpu.csv`:
  stdout/stderr запуска, GPU UUID/VRAM/загрузка/температура/мощность и фаза.
- `записи/0001/…`: TXT и JSON двух систем, параметры подготовки/прогрева,
  нативный журнал GigaAM со стеком SIGSEGV. Ответы Whisper сохраняются полностью.
- `условия.json`, `сводка.csv`, `отчёт.md`: входной корпус, SHA256, условия,
  статусы, границы таймеров и времена. Версии серверного Whisper помечены как
  сведения владельца от 07.10.2026, а не автоматическая проверка установки.
- `отчёт.html`, `графики/*.svg`: самодостаточный HTML и векторные графики;
  обновляются после каждой записи, не требуют интернета или matplotlib.
  График GPU показывает общую нагрузку всех процессов, не только стенда.
- `диагностика.tar.gz`: единый архив для передачи, включая логи и тексты
  разговоров. Аудио, веса моделей и .env в архив не входят.

Подготовленные WAV удаляются при завершении. Прежние результаты и кеши
не удаляются; Docker prune не вызывается. После SIGKILL/перезагрузки очистка и
упаковка автоматически не гарантируются. Повторов и автоматического возобновления
прогона нет. При ошибке сохраняется частичный отчёт.

GPU-зависимости закреплены: официальный GigaAM commit
`7447938d791c4f3e643386ee22c33777004293a5`, sherpa-onnx 1.13.4 CUDA12/cuDNN9 и
ONNX Runtime 1.24.4 в обеих библиотеках. Несовпадение версий проверяется до
сессий CAM++, поскольку прежнее смешивание Runtime приводило к SIGSEGV.

Исторический локальный режим `python -m benchmark.compare --phase local`
сохранён для прежних тестов; `run.sh` использует только серверную схему.
