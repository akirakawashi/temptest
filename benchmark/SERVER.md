# Запуск на сервере H100

Сначала весь корпус обрабатывает собственный тестовый Whisper. Он останавливается
и сохраняется, затем те же записи проходят полный GigaAM. После него тестовая
Ollama останавливается, и те же записи проходят GigaAM для первой линии:
VAD + ASR без определения собеседников, эмоций и GigaChat. Рабочие `whisper-asr`,
`model-proxy`, vLLM и worker не управляются, их API и секреты не используются.
Оба теста используют общую с ними GPU, поэтому могут влиять на задержки прода.

## Подготовка

После публикации изменений владельцем:

```bash
cd /home/aleksandr.ozherelev@ic-group.ru/dev/temptest
git pull --ff-only
cp -n benchmark/server.env.example .env
```

Папка записей уже находится рядом: `../audio`. Ключ Whisper больше не нужен.
Прежние `WHISPER_API_BASE_URL`, `WHISPER_API_KEY`, `WHISPER_API_MODEL` в `.env`
новым стендом не используются. `cp -n` сохраняет существующую `.env`; недостающие
новые параметры берутся из значений Compose по умолчанию. Полную `.env` прода
сюда копировать не нужно.

Тестовый Whisper по умолчанию использует закреплённый образ:

```dotenv
BENCH_WHISPER_IMAGE=hwdsl2/whisper-server@sha256:de716f26601229179eb4ba62d07e7a5ed4167c5290786281cd06535fdf2a97d6
BENCH_WHISPER_MODEL=large-v3
BENCH_WHISPER_THREADS=2
BENCH_WHISPER_BEAM=5
BENCH_EXPECTED_FILES=100
BENCH_API_GAP=5
BENCH_API_TIMEOUT=1200
```

Это тот же digest, что в конфигурации рабочего Whisper. Стенд проверяет
фактические версии faster-whisper 1.2.1/CTranslate2 4.8.1 и CUDA/float16;
несовпадение останавливает запуск. Другие параметры стенда явно сохранены
в отчёте; дополнительные настройки рабочего сервиса стенд не читает.

База уже содержит CUDA, Python, curl и PyAV. Клиент устанавливает HTTPX,
образ GigaAM — свои Python-пакеты в отдельное окружение. `apt` в сборках
отсутствует: прежний сбой обращения к `deb.debian.org` этим путём обходится.
Доступ к Docker registry, PyPI, PyTorch, GitHub и источникам весов по-прежнему
нужен. Реальная сборка и GPU-прогон выполняются владельцем на сервере.

CUDA-пакет `sherpa-onnx==1.13.4+cuda12.cudnn9` для CAM++ устанавливается
по прямой ссылке Hugging Face из [официального каталога CUDA wheels](https://k2-fsa.github.io/sherpa/onnx/cuda.html).
Сборке больше не требуется доступ к странице индекса `k2-fsa.github.io`,
на которой предыдущий запуск остановился с `Network is unreachable`.
Ревизия хранилища и SHA256 файла зафиксированы; пакет рассчитан на Python 3.12
и Linux x64. Он устанавливается отдельным слоем Docker, поэтому при сбое
его загрузки успешно собранные слои GigaAM и ONNX Runtime сохраняются в кеше.

Для импорта CUDA wheel нужна системная библиотека ALSA `libasound.so.2`,
даже когда распознаются файлы. Образ устанавливает `libasound2t64` и
`libasound2-data` для Ubuntu 24.04 по прямым ссылкам официального архива,
с проверкой SHA256, без `apt`. После установки сборка проверяет импорт
PyTorch, ONNX Runtime и sherpa-onnx без GPU, аудио и загрузки моделей.
Ошибка системных зависимостей теперь останавливает сборку до запуска Ollama
и замеров; успешный импорт ещё не заменяет проверку моделей на GPU.

Перед повторным прогоном сборку GigaAM можно проверить отдельно, без запуска
распознавания, подключения GPU и изменения работающих контейнеров:

```bash
cd /home/aleksandr.ozherelev@ic-group.ru/dev/temptest
set -o pipefail
BENCH_AUDIO_DIR="$(cd ../audio && pwd)" \
BENCH_OUT="$PWD/benchmark-results" \
BENCH_CACHE="$PWD/benchmark-cache" \
  docker compose --project-name speech-comparison \
    -f compose.benchmark.yml --progress plain build compare \
  2>&1 | tee /tmp/speech-build-gigaam.log
```

Сборка скачивает библиотеки и публичные модели. Аудиозаписи ей не передаются.
Полученный образ и кеш будут использованы следующим запуском `run.sh`.
Прежние результаты Whisper удалять не нужно.

Отдельные контейнеры загрузки весов по умолчанию используют сеть сервера
(`host`), обходя выход в интернет через Docker bridge. Это не меняет
сеть работающих контейнеров и настройки Docker. Доступность Hugging Face,
PyPI и остальных источников через сеть сервера всё равно необходима.
Загрузчики не имеют доступа к аудио и GPU; обработка записей остаётся
в собственных внутренних сетях стенда.

Ollama для скачивания слушает только `127.0.0.1:11435`, без загрузки LLM в GPU.
Перед `pull` скрипт ждёт готовности именно контейнера `ollama-download`.
Если этот порт занят, запуск остановится; другой свободный порт можно передать
как `BENCH_OLLAMA_DOWNLOAD_PORT=11436` перед командой. Тестовая Ollama для
обработки остаётся на `ollama:11434` внутри сети GigaAM.

При исправном выходе из Docker bridge сеть загрузчиков можно задать перед
командой: `BENCH_DOWNLOAD_NETWORK=bridge`. Сборка использует прежнюю
сеть `default`; её этапы выполняются отдельно от контейнеров загрузки.

## Запуск с выводом и сохранением логов

Из папки `temptest`:

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio
```

Дополнительный `tee` и фоновый запуск не нужны: скрипт пишет напрямую в
`логи/запуск.log`, а отдельный читатель показывает этот файл в терминале.
Остановившийся или медленный вывод SSH/VS Code не удерживает выполнение задач;
при завершении скрипт останавливает читателя. Длительный прогон удобно выполнять в tmux.
Скачивания дополнительно сохраняются в `логи/загрузка-whisper.log`,
`логи/загрузка-gigaam.log` и `логи/загрузка-llm.log`.

Это один новый запуск всех трёх режимов на смешанных 100 записях, без отборов
NCC/Телфина. Исходные записи преобразуются один раз в общий моно WAV;
все режимы проверяют его SHA256. Роли по исходным стереоканалам не восстанавливаются.
Обработка первой линии запускается в отдельном контейнере без сети и LLM.
Её подробный журнал — `логи/первая-линия-контейнер.log`.

Порог резерва остаётся настраиваемым: `BENCH_GPU_RESERVE_MIB=3072` задаёт
3 ГиБ, `BENCH_GPU_RESERVE_MIB=0` отключает порог свободной VRAM. Без явного
переопределения действует 4096 МиБ; на прежнем прогреве H100 этот порог
остановил запуск при 4023 МиБ. Проверка доступности GPU сохраняется при любом
значении. Снижение резерва увеличивает вероятность нехватки памяти на общей GPU.

Задачи запускаются без интерактивного ввода. Скрипт получает код завершения
через `docker wait`, одновременно показывает `docker logs --follow` и сохраняет
полный журнал контейнера в отдельный файл после завершения. Переход к следующему
этапу определяется кодом завершения контейнера. Если читатель логов не завершился
по SIGTERM за 3 секунды, скрипт завершает принудительно только этот процесс
Docker CLI, затем сохраняет полный журнал из Docker. В журнале есть явные
сообщения «Задача … завершена: код …» и «Запускаем тестовый Whisper на GPU».
Веса Whisper остаются в собственном кеше при прерывании и повторном запуске.

## Только полный цикл GigaAM

Если Whisper уже обработал корпус, повторно запускать его не требуется.
Режим `--gigaam-only` создаёт новый каталог результатов, заново готовит
моно PCM16 WAV 16 кГц из `../audio` вне замеров и запускает только GigaAM
с VAD, CAM++, эмоциями и LLM. Сервер и загрузчик Whisper не запускаются.
Этот прежний режим запускает только полный GigaAM. Для нового сравнения
всех трёх систем запускайте обычную команду без `--gigaam-only`.
Подготовка выполняется отдельным CPU-контейнером `audio-prepare` без сети
и GPU, в том же образе с теми же PyAV/NumPy, что подготовил вход для Whisper.
Если собственный тестовый Whisper ещё работает, скрипт остановится и попросит
сначала проверить его контейнер. Продовые сервисы не управляются.

После коммита и публикации изменений владельцем:

```bash
cd /home/aleksandr.ozherelev@ic-group.ru/dev/temptest
git pull --ff-only
```

Проверьте, что предыдущий запуск стенда остановлен:

```bash
docker ps --filter label=com.docker.compose.project=speech-comparison \
  --format 'table {{.Names}}\t{{.Status}}'
```

При пустом списке запустите независимо от SSH:

```bash
nohup env BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio --gigaam-only \
  > /tmp/gigaam-test-launch.log 2>&1 < /dev/null &
```

Просмотр логов:

```bash
tail -n 100 -f /tmp/gigaam-test-launch.log
```

Ctrl+C при просмотре останавливает только `tail`. `nohup` позволяет продолжить
запуск после обычного разрыва SSH. У foreground-запуска SIGHUP теперь фиксируется
как прерывание с кодом 129; незавершённый запуск не выдаёт код 0.

Отчёт `benchmark-results/<новый-ID>/отчёт.html`, графики и архив содержат
результаты GigaAM. Прежний каталог Whisper не изменяется. Для дальнейшего
сравнения сохраните оба каталога; совпадение входов проверяется по именам,
длительности и SHA256 PCM в `условия.json`. Нагрузка общей GPU и время запуска
могут различаться между прогонами. Удалять контейнеры, результаты и кеши не нужно.

По умолчанию ожидаются 100 файлов, включая подпапки. Для предварительного
прогона используйте отдельную папку с двумя записями:

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio-smoke --expected-files 2
```

Для прогрева берутся первые 30 секунд первой записи. Если там нет речи:

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio --warmup-file /recordings/запись-с-речью.mp3
```

Пути в параметрах прогона указываются внутри контейнера: вход — `/recordings`.
При неверном числе файлов, превышении 30 минут/64 МиБ PCM WAV аудиозапросов
нет. При HTTP-ошибке/таймауте прекращаются следующие записи и фаза GigaAM;
повторов и автоматического возобновления нет. Частичные результаты сохраняются.

## Ресурсы и завершение

Параметры команды допускают штатную загрузку H100 до 100% и требуют ≥12 ГиБ
свободной VRAM перед загрузкой каждой системы. Также нужны ≥20 ГиБ доступной
RAM и ≥32 ГиБ свободного диска для результатов, кеша и Docker. Значения
фиксируются в отчёте, фактическая общая нагрузка GPU — в `логи/gpu.csv`.

Монитор проверяет резерв 4 ГиБ примерно раз в 2 секунды и останавливает
только тестовую систему при его нарушении или невозможности проверки GPU.
Whisper также проверяет резерв сразу после загрузки модели, GigaAM — после
загрузки компонентов и прогрева. RAM: сервер Whisper 8 ГиБ, клиент 2 ГиБ,
GigaAM 8 ГиБ, Ollama 10 ГиБ. Эти лимиты RAM не ограничивают VRAM аппаратно.

Для общей H100 стенд задаёт `BENCH_LLM_NUM_BATCH=64` вместо батча 1024,
который использовала Ollama в остановленном запуске, и
`BENCH_LLM_KV_CACHE_TYPE=q8_0` вместо `f16`. Батч уменьшает рабочие буферы,
тип кеша уменьшает память контекста; веса Q4_K_M и контекст 8192 сохраняются.
[Ollama описывает](https://docs.ollama.com/faq#how-can-i-set-the-quantization-type-for-the-kv-cache)
небольшую потерю точности при `q8_0`; кеш относится к LLM и не меняет
распознавание GigaAM. Размер батча и кеш могут изменить время полного цикла.
Настройки записываются в `условия.json`, `gigaam-подготовка.json` каждой
записи и HTML-отчёт; фактические `n_batch` и тип кеша видны в `логи/ollama.log`.
Можно переопределить их перед командой запуска: батч 32–1024,
кеш `f16`, `q8_0` или `q4_0`. Нужный запас на общей GPU подтверждается
прогревом на сервере; монитор резерва 4 ГиБ продолжает работать.

При успехе, ошибке или Ctrl+C скрипт останавливает только контейнеры своего
прогона. Контейнеры и сети `speech-comparison` остаются для просмотра логов;
автоматическое удаление отключено. Завершённые вспомогательные контейнеры
получают уникальное имя прогона, поэтому не мешают следующему запуску.
Сервисы Whisper/Ollama при следующем запуске запускаются через Compose.
Кеши сохраняются; исходные записи подключены только для чтения.
Одновременные запуски из одной папки блокируются.

## Что передать для разбора

В конце выводится путь `benchmark-results/<дата-ID>/отчёт.html` и архив
`диагностика.tar.gz` из той же папки. HTML открывается офлайн; графики уже
внутри. Достаточно передать архив нужного запуска. Он содержит тексты
разговоров, результаты, логи сервера Whisper/Ollama и процессов GigaAM,
но не аудио, модели или `.env`.

Для нового тройного прогона передайте всю папку запуска или этот архив.
В `итоги.json` и `замеры.csv` сохранены данные для будущего общего отчёта;
HTML уже содержит графики трёх режимов, реальные средние проценты этапов
и тексты для сравнения. Файлы в `записи/0001/` имеют отдельные имена
`whisper`, `gigaam` и `gigaam_first_line`. Результаты записываются после
каждого файла; при ошибке обработка прекращается и архив сохраняет частичные данные.
Прежние результаты, контейнеры, кеши и исходное аудио перед новым запуском
удалять не нужно. Работающий предыдущий запуск этого же стенда блокирует новый.

Чистое ASR-время Whisper API не сообщает: в таблице используется полное время
HTTP-запроса. GigaAM сообщает отдельно ASR и полный цикл; времена её этапов
могут пересекаться. Для процентов точности требуется эталонная расшифровка.
