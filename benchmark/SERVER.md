# Прогон 100 записей на сервере с работающим Whisper

Перенесите код стенда и используйте отдельную папку со 100 записями. Рабочий
Whisper продолжает обслуживать свой API, без перезапуска и перенастройки.
Стенд отправляет по одной записи с паузой, затем запускает отдельную GigaAM.

## Код из GitHub

Новый репозиторий стенда — `https://github.com/akirakawashi/temptest`.
После публикации изменений владельцем на сервере:

```bash
mkdir -p /srv/speech-test/audio
cd /srv/speech-test
git clone https://github.com/akirakawashi/temptest.git
cd temptest
cp -n benchmark/server.env.example .env
chmod 600 .env
```

Заполните ключ и адрес API по инструкции ниже, затем запускайте:

```bash
BENCH_GPU=0 bash benchmark/run.sh /srv/speech-test/audio
```

Для последующих обновлений используйте `git pull --ff-only` внутри
`/srv/speech-test/temptest`. Описанный далее архив — альтернативный способ
передачи кода, его папка при распаковке называется `speech-comparison`.

## Подготовка

H100 NVL подходит. В вашем снимке от 07.10.2026 свободно 14600 МиБ VRAM,
это ниже стартового порога стенда 16384 МиБ. При таком состоянии прогон
завершится с кодом 42 ещё до аудиозапросов. Выберите окно с достаточным
свободным ресурсом; чужие сервисы скрипт не останавливает. Также нужны ≥20 ГиБ
доступной RAM, свободные CPU 0–3 или выбранный CPUSET и минимум 32 ГиБ
свободного диска на файловых системах результатов, кеша и Docker.

Нужны Docker/Compose, NVIDIA Container Toolkit, Bash, flock, tar, timeout,
интернет для подготовки и доступ контейнера к адресу Whisper.

```bash
nvidia-smi
docker compose version
docker run --rm --gpus device=0 ubuntu:24.04 nvidia-smi
```

Последняя команда только проверяет доступ GPU; inference не запускает.
Если доступ отсутствует, следуйте
[инструкции NVIDIA](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html).
Изменения Docker daemon на рабочем сервере выполняет его администратор.

Исходники можно передать архивом, собранным локально:

```bash
python3 benchmark/package.py --out ../speech-comparison-server-api.tar.gz
```

Архив не содержит .env, аудио, результатов, Git или весов. Рядом создаётся SHA256,
внутри — MANIFEST.json с контрольными суммами исходников.

```bash
ssh USER@SERVER 'mkdir -p ~/speech-test/audio'
scp speech-comparison-server-api.tar.gz speech-comparison-server-api.tar.gz.sha256 USER@SERVER:~/speech-test/
rsync -av --progress /path/to/audio100/ USER@SERVER:~/speech-test/audio/
```

Если аудио уже есть на сервере, не копируйте его, используйте существующий путь.
На сервере:

```bash
cd ~/speech-test
sha256sum -c speech-comparison-server-api.tar.gz.sha256
tar -xzf speech-comparison-server-api.tar.gz
cd speech-comparison
cp -n benchmark/server.env.example .env
chmod 600 .env
```

Отредактируйте `.env` на сервере:

```dotenv
WHISPER_API_BASE_URL=http://10.220.21.2:8002/v1
WHISPER_API_KEY=КЛЮЧ_КЛИЕНТА_MODEL_PROXY
WHISPER_API_MODEL=large-v3
BENCH_EXPECTED_FILES=100
BENCH_API_GAP=5
BENCH_API_TIMEOUT=1200
```

Для порта 8002 нужен ключ клиента `model-proxy`, например выданный для dev.
Это не внутренний ключ из `secrets/whisper.env`: nginx подставляет его сам.
Ключ остаётся в вашем .env, не передавайте его вместе с логами. Не публикуйте
полный вывод `docker inspect`/`docker compose config`: он может раскрыть секреты.
API-клиент допускает только локальный IP, не следует HTTP-редиректам и не
использует HTTP_PROXY/HTTPS_PROXY. Существующий Whisper отдельно не меняется.

Если .env уже существовал, `cp -n` его сохранит; внесите недостающие параметры
вручную. Полную .env рабочего стека сюда копировать не нужно.

## Запуск

Для предварительного теста используйте отдельную папку с двумя файлами,
без копий внутри основной папки корпуса:

```bash
BENCH_GPU=0 bash benchmark/run.sh ../audio-smoke --expected-files 2
```

Для 100 записей:

```bash
BENCH_GPU=0 BENCH_THREADS=4 BENCH_CPUSET=0-3 bash benchmark/run.sh ../audio
```

Все поддерживаемые форматы во вложенных папках учитываются. При количестве
файлов, отличном от ожидаемого, или записи длиннее 30 минут/64 МиБ WAV
аудиозапросы не отправляются. Отдельный прогрев можно выбрать:

```bash
BENCH_GPU=0 bash benchmark/run.sh ../audio --warmup-file /recordings/речь.mp3
```

Для длинного запуска используйте tmux, либо:

```bash
nohup env BENCH_GPU=0 BENCH_THREADS=4 BENCH_CPUSET=0-3 \
  bash benchmark/run.sh ../audio > /tmp/speech-test-console.log 2>&1 < /dev/null &
```

Основной журнал всё равно сохраняется внутри папки результатов; /tmp-файл
нужен только для отсоединённой оболочки. Не запускайте параллельно копии стенда:
Docker-проект фиксирован (`speech-comparison`).

## Последовательность

1. Проверяются свободная VRAM, загрузка GPU и RAM. При недостатке нет запросов.
2. Собирается лёгкий клиент, проверяются корпус, /health и авторизация /v1/models.
3. Все записи последовательно идут в рабочий Whisper. Время — полный запрос.
   Пауза минимум 5 с, проверка здоровья перед следующей записью, повторов нет.
4. После успеха проверяются ресурсы, собирается CUDA-образ и скачиваются веса
   в контейнерах без записей и без GPU. Затем снова проверяются ресурсы.
5. Собственная Ollama и GigaAM запускаются в изолированной сети. Все записи
   проходят полный цикл, с отдельными ASR/этапными таймерами и прогревом.
6. Свои контейнеры останавливаются, подготовленные WAV удаляются, отчёт и
   архив диагностики завершаются. Рабочий Whisper остаётся запущенным.

На любом HTTP-сбое или таймауте Whisper новые записи и GigaAM не запускаются.
После клиентского таймаута последний запрос может ещё обрабатываться сервисом;
не отправляйте его сразу повторно вручную. Ошибка GigaAM останавливает её фазу,
частичные результаты сохраняются. Автоматического возобновления нет.

Во время GigaAM резерв свободной VRAM — 4096 МиБ. При его нарушении монитор
останавливает только контейнер текущего прогона и Ollama стенда. RAM ограничена
8 ГиБ для GigaAM и 10 ГиБ для Ollama. Полной изоляции вычислений на общей GPU
это не даёт; выберите тихое окно. Порог запуска не является лимитом VRAM.

## Результаты

Все файлы одного запуска — в `benchmark-results/<дата-ID>/`:

```text
отчёт.html                 открыть в браузере, графики уже внутри
отчёт.md / сводка.csv       времена и статусы
условия.json               корпус, SHA256, параметры, версии, ограничения
прогон.log                 подробный русский журнал
графики/                   SVG по времени, этапам и общей GPU
логи/                      запуск, Ollama, GPU CSV, причины защитной остановки
записи/0001/…              тексты, JSON, прогрев, подготовка и native-логи
диагностика.tar.gz          единый файл для передачи
```

Архив включает тексты разговоров и все диагностические данные, но не включает
аудио, модели или ключ API. Ничего автоматически не отправляется наружу.
Графики обновляются после каждой записи, работают офлайн. Времена этапов
GigaAM могут пересекаться. На графике GPU — общая нагрузка сервера.

```bash
rsync -av USER@SERVER:~/speech-test/speech-comparison/benchmark-results/ ./server-benchmark-results/
```

Можно передать только `диагностика.tar.gz` нужного запуска. CSV содержит
полное время Whisper API, объединённую длительность сегментов с текстом,
время GigaAM ASR, полного цикла и отдельных этапов. Это не проценты точности:
для них требуется эталонная расшифровка.

Настройки распознавания рабочего Whisper стенд не переписывает: исправление
его повторов в эти изменения не входит. Скорость и проценты нужно считать
из этого серверного прогона; прежние числа RTX 4070 к H100 не применяются.
