# Запуск на сервере H100

Три теста запускаются по одному: Whisper, GigaAM через TensorRT, T-one через
TensorRT. Рабочие `whisper-asr`, `model-proxy`, vLLM и worker не управляются,
их API и секреты не используются. Тесты используют общую с ними GPU, поэтому
могут влиять на задержки прода.

## Подготовка

После публикации изменений владельцем:

```bash
cd /home/aleksandr.ozherelev@ic-group.ru/dev/temptest
git pull --ff-only
cp -n benchmark/server.env.example .env
```

Папка записей уже находится рядом: `../audio`. Ключ Whisper не нужен.
`cp -n` сохраняет существующую `.env`; недостающие параметры берутся из значений
Compose по умолчанию. Полную `.env` прода сюда копировать не нужно.

Тестовый Whisper по умолчанию использует закреплённый образ:

```dotenv
BENCH_WHISPER_IMAGE=hwdsl2/whisper-server@sha256:de716f26601229179eb4ba62d07e7a5ed4167c5290786281cd06535fdf2a97d6
BENCH_WHISPER_MODEL=large-v3
BENCH_WHISPER_THREADS=2
BENCH_WHISPER_BEAM=5
BENCH_EXPECTED_FILES=100
BENCH_API_GAP=5
BENCH_API_TIMEOUT=1200
```

Это тот же digest, что в конфигурации рабочего Whisper. Стенд проверяет
фактические версии faster-whisper 1.2.1/CTranslate2 4.8.1 и CUDA/float16;
несовпадение останавливает запуск. Параметры стенда сохраняются в отчёте;
дополнительные настройки рабочего сервиса стенд не читает.

База уже содержит CUDA, Python, curl и PyAV. `apt` в сборках отсутствует.
Доступ к Docker registry, PyPI, PyTorch, GitHub и источникам весов нужен
для сборки образов и первой загрузки моделей.

Контейнеры загрузки весов по умолчанию используют сеть сервера (`host`),
обходя выход в интернет через Docker bridge. Это не меняет сеть работающих
контейнеров и настройки Docker. Загрузчики не имеют доступа к аудио и GPU;
обработка записей остаётся во внутренних сетях стенда. При исправном выходе
из Docker bridge сеть загрузчика Whisper можно задать перед командой:
`BENCH_DOWNLOAD_NETWORK=bridge`.

## Whisper

Из папки `temptest`:

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio
```

Дополнительный `tee` и фоновый запуск не нужны: скрипт пишет напрямую в
`логи/запуск.log`, а отдельный читатель показывает этот файл в терминале.
Остановившийся или медленный вывод SSH/VS Code не удерживает выполнение задач.
Отключение SSH прерывает запуск с кодом 129; длительный прогон удобно
выполнять в tmux. Скачивание весов дополнительно сохраняется в
`логи/загрузка-whisper.log`.

Порог резерва настраивается: `BENCH_GPU_RESERVE_MIB=3072` задаёт 3 ГиБ,
`BENCH_GPU_RESERVE_MIB=0` отключает порог свободной VRAM. Без явного
переопределения действует 4096 МиБ. Проверка доступности GPU сохраняется при
любом значении. Снижение резерва увеличивает вероятность нехватки памяти
на общей GPU.

Задачи запускаются без интерактивного ввода. Скрипт получает код завершения
через `docker wait`, одновременно показывает `docker logs --follow` и сохраняет
полный журнал контейнера в отдельный файл после завершения. В журнале есть
явные сообщения «Задача … завершена: код …» и «Запускаем тестовый Whisper
на GPU». Веса остаются в собственном кеше при прерывании и повторном запуске.

По умолчанию ожидаются 100 файлов, включая подпапки. Для предварительного
прогона используйте отдельную папку с двумя записями:

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio-smoke --expected-files 2
```

Для прогрева берутся первые 30 секунд первой записи. Если там нет речи:

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 \
  bash benchmark/run.sh ../audio --warmup-file /recordings/запись-с-речью.mp3
```

Пути в параметрах прогона указываются внутри контейнера: вход — `/recordings`.
При неверном числе файлов, превышении 30 минут/64 МиБ PCM WAV аудиозапросов
нет. При HTTP-ошибке или таймауте следующие записи не отправляются; повторов
и автоматического возобновления нет. Частичные результаты сохраняются.

## GigaAM и T-one через TensorRT

```bash
BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 BENCH_GPU_RESERVE_MIB=3072 \
  bash benchmark/run-gigaam-trt.sh ../audio

BENCH_GPU=0 BENCH_GPU_MIN_FREE_MIB=12288 BENCH_GPU_MAX_UTIL=100 BENCH_GPU_RESERVE_MIB=3072 \
  bash benchmark/run-tone-trt.sh ../audio
```

Оба теста обрабатывают все записи папки подряд, без пауз; число записей не ограничено.
`--parallel 5` обрабатывает пять записей одновременно: займёт 10 ядер процессора (с нулевого
по девятое) и сильнее нагрузит общую видеокарту. Набор ядер меняет `BENCH_CPUSET`.
Подготовка, замеры и файлы результатов — в [GIGAAM-TRT.md](GIGAAM-TRT.md) и
[TONE-TRT.md](TONE-TRT.md). `--reference-run benchmark-results/<прогон>` сверяет
корпус с прежним прогоном. Если `nvcr.io` отвечает 403, образ Triton загружается
через прокси: `python3 benchmark/fetch_triton_image.py --load`.

Оба клиента собираются поверх общего образа библиотек
`speech-comparison:4.0.0-gigaam-cuda`. Если его нет, скрипт соберёт его сам.
Сборку можно проверить отдельно, без запуска распознавания и подключения GPU:

```bash
cd /home/aleksandr.ozherelev@ic-group.ru/dev/temptest
set -o pipefail
docker compose -f compose.trt-base.yml --progress plain build base \
  2>&1 | tee /tmp/speech-build-trt-base.log
```

Сборка скачивает библиотеки. Аудиозаписи ей не передаются.

## Ресурсы и завершение

Параметры команд допускают штатную загрузку H100 до 100% и требуют ≥12 ГиБ
свободной VRAM перед запуском. Также нужны ≥20 ГиБ доступной RAM (тестам
TensorRT — 24 ГиБ) и ≥32 ГиБ свободного диска для результатов, кеша и Docker.
Пороги задаются переменными `BENCH_MIN_RAM_MIB` и `BENCH_MIN_DISK_MIB`.
Значения фиксируются в отчёте, фактическая общая нагрузка GPU — в `логи/gpu.csv`.

Монитор проверяет резерв VRAM примерно раз в 2 секунды и останавливает
только тестовую систему при его нарушении или невозможности проверки GPU.
Whisper также проверяет резерв сразу после загрузки модели. Лимиты RAM
контейнеров не ограничивают VRAM аппаратно.

При успехе, ошибке или Ctrl+C скрипт останавливает только контейнеры своего
прогона. Контейнеры и сети стенда остаются для просмотра логов;
автоматическое удаление отключено. Завершённые вспомогательные контейнеры
получают уникальное имя прогона, поэтому не мешают следующему запуску.
Кеши сохраняются; исходные записи подключены только для чтения.
Одновременные запуски из одной папки блокируются.

Проверить, что предыдущий запуск остановлен:

```bash
docker ps --filter name=speech-comparison --format 'table {{.Names}}\t{{.Status}}'
```

## Что передать для разбора

В конце выводится путь к папке запуска; в ней `отчёт.html` и архив
`диагностика.tar.gz`. HTML открывается офлайн. Достаточно передать архив
нужного запуска. Он содержит тексты разговоров, результаты и логи,
но не аудио, модели или `.env`.

Результаты записываются после каждого файла; при ошибке обработка прекращается
и архив сохраняет частичные данные. Прежние результаты, контейнеры, кеши
и исходное аудио перед новым запуском удалять не нужно.

Чистое ASR-время Whisper API не сообщает: в таблице используется полное время
HTTP-запроса. Для процентов точности требуется эталонная расшифровка.
